# v8 WP-15 / WP-16

## Capture to Digital Twin

The digital-twin service builds a draft Simulator model from live Register Lab evidence without starting a server or arming writes.

Safety defaults:

- generated Coil and Holding Register areas are read-only unless explicitly selected otherwise;
- Discrete Inputs and Input Registers remain read-only;
- inferred or low-confidence points are marked as uncertain with source/evidence metadata;
- applying a draft creates Simulator configuration only;
- a generated server cannot run until a separate explicit approval call is made;
- source connection, Unit IDs, raw values, definitions and evidence identifiers are retained as provenance.

API routes are available under `/api/v8/digital-twins` when `digitalTwinWorkspace` is enabled.

## Automation / CLI / SDK

The JavaScript automation client defaults to loopback-only API access and requires an explicit remote opt-in. Write helpers cannot issue a request without explicit write confirmation and enforce separate bulk/broadcast confirmations.

CLI examples:

```bash
npm run v8:cli -- status --json
npm run v8:cli -- connections --json
npm run v8:cli -- read --connection meter-1 --unit 1 --fc 3 --address 0 --quantity 10 --json
npm run v8:cli -- write --connection meter-1 --unit 1 --fc 6 --address 10 --value 25 --confirm --json
npm run v8:cli -- recipe-run ./recipe.json --connection meter-1 --json
```

JavaScript SDK entry point: `sdk/js/index.js`.

Dependency-free Python example client: `sdk/python/modbus_workbench_client.py`.
